Verdict Watch

The invalidation primitive for verified claims — by Cumulative Web Inc

Verification verdicts go stale. A claim verified in September can silently rot — the playlist changes, the page moves, the evidence dies — while every badge still says VERIFIED. Verdict Watch re-checks the evidence behind signed trust claims and reports STILL_VALID / CHANGED / DEAD / UNREACHABLE with diffs. Drift is flagged for human review — claims are never auto-downgraded, because false invalidation is worse than stale verification.

Deep link: ?watch=<envelope-url> pre-fills this form. Your watch list is stored locally in your browser.

Honest limits.
  • Browser checks are best-effort: some evidence URLs block cross-origin reads (CORS). Blocked reads report UNREACHABLE with a CORS note — not DEAD.
  • Spotify playlist pages are dynamic shells, so Verdict Watch checks the playlist's oEmbed title (reachability + identity), not track positions. Position-level re-scans need the Spotify API.
  • A CHANGED or DEAD verdict is a flag for human review, never an automatic downgrade of the claim. The trust log is append-only: corrections arrive as new envelopes, old proofs are never rewritten.
  • Server-side runs (same engine, Node) are authoritative; this page runs the identical engine in your browser.

Verify it yourself

Don't take our word for it — re-run the check from your own machine or your own agent runtime.

  • In your browser: the re-verification UI — paste any trust-log claim envelope URL and it re-checks it itself: STILL_VALID / CHANGED / DEAD / UNREACHABLE, with diffs; ?watch=<envelope-url> deep links pre-fill the form.
